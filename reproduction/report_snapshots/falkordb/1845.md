# `DELETE` inside a subquery may report `count(r) = 0` and leave the deleted path visible on a later row

- Public issue: https://github.com/FalkorDB/FalkorDB/issues/1845
- DBMS: FalkorDB
- Observed version: `4.16.8`
- Maintainer status in frozen audit: confirmed
- Fix status in frozen audit: fixed

## Minimized setup

```cypher
MATCH (n) DETACH DELETE n;
CREATE (a:Person {name:'Alice'})-[:WORKS_FOR]->(b:Person {name:'Bob'}),
       (c:Person {name:'Charlie'})-[:WORKS_FOR]->(b);
```

## Minimized trigger

```cypher
MATCH (employee:Person)-[:WORKS_FOR]->(p)
WITH employee, p
CALL {
  WITH employee, p
  MATCH (employee)-[r:WORKS_FOR]->(p)
  DELETE r
  RETURN count(r) AS deleted
}
RETURN employee.name AS employee_name, p.name AS manager_name, deleted
ORDER BY employee_name
```

## Expected and actual results

Neo4j `2026.03.1` returns:

```text
Alice, Bob, 1
Charlie, Bob, 1
```

FalkorDB `4.16.8` returns:

```text
Alice, Bob, 1
Charlie, Bob, 0
```

The second relationship exists and is deleted, but the subquery reports zero.
The public issue also records a stronger variant in which an immediately later
optional variable-length match still observes that deleted path.
