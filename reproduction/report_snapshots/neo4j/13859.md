# OPTIONAL MATCH with DISTINCT and ORDER BY returns different coalesce result across runtimes

Reviewed offline evidence snapshot for https://github.com/neo4j/neo4j/issues/13859.

- DBMS/version: Neo4j Community `2026.06.0`
- Cypher version: 25
- Maintainer status in frozen audit: confirmed
- Fix status in frozen audit: fixed
- Cached issue source: `data/oracle2_smoke/neo4j_silence6666668_issue_details_20260815.json`

## Setup

The test label must contain no nodes.

```cypher
CYPHER 25
MATCH (n:Missing) DETACH DELETE n;
```

## Minimized trigger

```cypher
CYPHER 25 runtime = slotted
OPTIONAL MATCH (n:Missing)-->(m)
RETURN DISTINCT coalesce(n.name, '') AS v ORDER BY v;
```

## Actual behavior

The `slotted` and `pipelined` runtimes return one row whose `v` is `null`.

```text
v
NULL
```

## Expected behavior

All runtimes should return one row whose `v` is the empty string.

```text
v
""
```

## Runtime and clause controls

The equivalent `parallel` runtime query returns the expected empty string:

```cypher
CYPHER 25 runtime = parallel
OPTIONAL MATCH (n:Missing)-->(m)
RETURN DISTINCT coalesce(n.name, '') AS v ORDER BY v;
```

Removing `ORDER BY` also returns the expected empty string on `slotted`:

```cypher
CYPHER 25 runtime = slotted
OPTIONAL MATCH (n:Missing)-->(m)
RETURN DISTINCT coalesce(n.name, '') AS v;
```
